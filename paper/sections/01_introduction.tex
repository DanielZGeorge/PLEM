\section{Introduction}
\label{sec:intro}

Segmentation maps of overhead imagery mix feature types with different geometry. Roads are
\emph{linear} features, one-dimensional structures only a few pixels wide; building footprints are
\emph{polygonal}, two-dimensional regions; and \emph{point} features are small, discrete locations
that matter as instances rather than as areas. In our trained-model pipeline the point feature is
the \emph{road intersection}, the place where two or more roads meet. Navigation, routing and map
conflation depend on these vertices of the road network, yet a pixel mask of roads does not mark
them. A single tile covering a city block can contain all three feature types. Pixel IoU, the
standard score for segmentation quality, treats every class as a region-overlap problem, and this
fails for linear features: since a road is only a few pixels wide, its IoU denominator is dominated
by the pixels most affected by sub-pixel registration noise, centerline jitter and predicted-width
error, none of which say whether the road network was extracted correctly. The same problem
applies to training. The usual multiclass segmentation losses, cross-entropy and soft Dice, have
no notion of tolerance, centerline topology or point instances, so a model trained with them is
only pushed to match pixels.

Table~\ref{tab:failure-modes} shows five scenarios on a controlled $128\times128$ synthetic scene
(a 3px-wide vertical road and a $40\times40$ building, with the full setup in
Section~\ref{sec:motivation}), computed with our metrics library, and shows where IoU's verdict
departs from the actual quality of a prediction. One scenario also fools DTAF1, which was designed
to fix IoU's problem: with 33\% of road pixels deleted at random, DTAF1 still reports a perfect
1.000. This motivates DTAF1-Topo
(Section~\ref{sec:topological}).

Every input shares one representation: an $H\times W$ \texttt{uint8} NumPy array of class labels,
with $0=$ background, $1=$ road, $2=$ building and an optional $3=$ point feature. Since a road
intersection lies \emph{on} a road pixel, the trained-model pipeline stores intersections as a
separate point layer per tile (an $(N,2)$ array of pixel coordinates, rasterized to a binary mask
when needed) instead of as class 3 in the label map, and the evaluation functions accept either
form (Section~\ref{subsec:pointf1}). Tolerances in the library are given in pixels but are meant to
be derived from a tile's ground sample distance (GSD), $d = \text{physical\_metres} /
\text{GSD\_metres\_per\_pixel}$, so that one physical tolerance (for example, 3 metres of
centerline error) applies the same way to imagery of different resolutions.
Section~\ref{sec:method} uses the same class convention on batched torch tensors, with channel
index equal to class id, so one \texttt{class\_config} dict serves both an evaluation call
(\texttt{dtaf1()}) and a training loss (\texttt{ToleranceBandLoss}).

This paper makes nine contributions:

\begin{enumerate}
  \item \textbf{A differentiable multi-task training loss} (Section~\ref{sec:method}). Its three
    geometric terms relax three of our own evaluation metrics, each following earlier work: a
    soft tolerance band for DTAF1, soft-clDice \cite{shit2021cldice} and a
    CenterNet-style Gaussian heatmap for points. A masked multi-source scheme lets datasets that
    annotate different features supervise one model, since no single source annotates every
    feature type (SpaceNet has roads, buildings and road intersections, while Potsdam and
    SpaceNet6 have buildings only), and an independent sigmoid point head keeps point supervision
    out of the segmentation softmax. We validate the loss with controlled synthetic ablations, a
    small joint-training run on 153 real tiles and a production-scale joint-training pipeline on
    1,033 tiles from three sources (Sections~\ref{sec:expsetup}--\ref{sec:results}).
  \item \textbf{DTAF1} (Section~\ref{sec:evalprotocol}), a tolerance-radius F1 that scores linear and polygonal classes with one formula and one code path, so scoring a
    newly added feature type only needs a configuration change.
  \item \textbf{CBHM} (Section~\ref{sec:evalprotocol}), a harmonic mean of clDice and boundary F1
    deliberately designed as the harsh foil of DTAF1, so that one feature type failing outright
    cannot be hidden by the other succeeding.
  \item \textbf{\texttt{dtaf1\_weighted} / \texttt{cbhm\_soft}} (Section~\ref{sec:composite}),
    companions to DTAF1 and CBHM weighted by ground-truth pixel count, which soften the collapse
    caused by a single failing class. A real failure case on SpaceNet imagery
    (\texttt{Khartoum\_img371}) motivated them.
  \item A raster-only approximation of \textbf{APLS} (Section~\ref{sec:evalprotocol}), needed
    because the model predicts a road mask rather than a graph, so there is no predicted vector
    graph to compare; and \textbf{DTAF1-Topo} (Section~\ref{sec:topological}), which folds this
    connectivity term into DTAF1 and closes the road-breakage blind spot shown in
    Table~\ref{tab:failure-modes}.
  \item \textbf{\texttt{point\_f1}} (Section~\ref{sec:evalprotocol}), a point-feature metric that
    matches instances with the Hungarian algorithm rather than greedy nearest-neighbor
    assignment, which avoids a specific adversarial failure mode. We apply it to road
    intersections derived from the vector road labels (Section~\ref{subsec:scaled-setup}), so
    point and road ground truth come from one annotation of the same image and cannot disagree.
  \item Empirical validation (Sections~\ref{sec:expsetup}--\ref{sec:results}) covering nine
    synthetic sensitivity sweeps of the evaluation metrics, seven synthetic loss-ablation sweeps,
    a curated real-data sample from SpaceNet (four cities) and ISPRS Potsdam, and three
    trained-model pipelines scored end to end with the library.
  \item \textbf{A production-scale validation and development record}
    (Sections~\ref{subsec:scaled-setup},~\ref{subsec:scaled-results}): a 1,033-tile, three-source
    pipeline trained six times for 40 epochs on cloud GPUs. Each run exposed one concrete failure
    mode, which we traced to its cause and fixed in code: an unreachable heatmap target, a
    mis-normalized negative term, a point channel flooding the segmentation softmax, an
    unlearnable point label, a negative-term normalization that swung between over- and
    under-detection, and incomplete public building labels (only 64\% of SpaceNet road-tile area
    has building ground truth). The final model reaches SpaceNet \texttt{cbhm\_soft} 0.685 and
    road-intersection F1 0.279.
  \item \textbf{A matched conventional-training baseline}
    (Sections~\ref{subsec:baseline-setup},~\ref{subsec:baseline-results}): the same pipeline
    trained with cross-entropy and Dice and selected on mIoU. On SpaceNet the two models tie on
    mIoU (0.570 vs.\ 0.572), while every PLEM metric favours the joint loss and the two kinds of
    metric rank tiles differently, with per-tile differences of opposite sign on 30 of 83 tiles.
    This shows on real data that conventional metrics and PLEM's metrics measure different
    things.
\end{enumerate}
