\section{A Differentiable Multi-Task Loss for Joint 0D/1D/2D Extraction}
\label{sec:method}

The metrics of Sections~\ref{sec:evalprotocol}--\ref{sec:topological} can only be used for
evaluation. DTAF1, boundary F1 and APLS are built on \texttt{scipy.ndimage.distance\_transform\_edt},
clDice on \texttt{skimage.morphology.skeletonize}, and point F1 on
\texttt{scipy.optimize.linear\_sum\_assignment}. Each of these operations is discrete and breaks
autograd, so none of them can serve directly as a training loss. This section introduces
\texttt{losses/}, a separate top-level package of differentiable training losses written in pure
\texttt{torch} alongside \texttt{metrics/} and \texttt{datasets/}. Each loss is an analog of one
metric from Section~\ref{sec:evalprotocol}, mirroring it in spirit without sharing code, since
numpy and scipy code cannot share an implementation with torch tensors inside an autograd graph.
With these losses one model can learn point (0D), linear (1D) and polygonal (2D) features jointly.

\subsection{Design Principle: Differentiable Analogs, Not Shared Code}
\label{subsec:method-principle}

\texttt{losses/} follows the standard PyTorch segmentation convention of $(B,C,H,W)$ logits and
$(B,H,W)$ int64 label maps with channel index equal to class id, instead of the $H\times W$ numpy
label maps of Section~\ref{sec:evalprotocol}. Table~\ref{tab:correspondence} summarizes the
correspondence and, for each term, what had to change relative to its evaluation counterpart to
make it differentiable.

\texttt{PLEMMultiTaskLoss} (Section~\ref{subsec:multitask-loss}) combines
\texttt{ToleranceBandLoss}, \texttt{SoftClDiceLoss} and \texttt{PointHeatmapLoss} with a CE+Dice
base term; \texttt{SoftBoundaryLoss} is available but not part of it.

\subsection{Soft Tolerance-Band Loss (DTAF1 Analog)}
\label{subsec:tolerance-loss}

DTAF1's precision test only needs a distance transform from the ground truth, while its recall
test needs one from the prediction. Precision needs only a
ground-truth dilation mask of radius $d$ (equivalent to $\mathrm{dist\_from\_gt} \le d$), which is
fixed target construction and can be precomputed once per batch under \texttt{no\_grad}. Recall is
the harder direction on the evaluation side, because it distance-transforms the prediction.
\texttt{F.max\_pool2d} is differentiable, however, so applying it iteratively to the model's own
soft probability map (soft-dilating it) keeps gradients flowing without any detach:
\begin{align}
  \mathrm{gt\_band}_c &= \mathrm{dilate}(G_c, d_c) \quad \text{(precomputed, no\_grad)} \\
  \mathrm{precision}_c &= \frac{\sum(p_c \cdot \mathrm{gt\_band}_c) + \epsilon}{\sum(p_c) + \epsilon} \\
  \mathrm{recall}_c &= \frac{\sum(g_c \cdot \mathrm{soft\_dilate}(p_c, d_c)) + \epsilon}{\sum(g_c) + \epsilon} \\
  \mathrm{loss}_c &= w(1-\mathrm{precision}_c) + (1-w)(1-\mathrm{recall}_c)
\end{align}
where $p_c$ is the model's softmax probability for class $c$ and $g_c$ is the one-hot ground-truth
mask. Both denominators use epsilon smoothing, as soft Dice does, so a class absent from both
prediction and ground truth tends toward the ``both empty $\to$ perfect'' convention without a
separate branch.

\begin{lstlisting}[language=Python, caption={\texttt{losses/tolerance.py}}]
def soft_tolerance_pair_loss(pred_soft, gt_hard, radius, eps=1e-6, precision_weight=0.5):
    gt_band = _dilate_binary(gt_hard.unsqueeze(1), radius)[:, 0]
    dilated_pred = soft_dilate_prob(pred_soft.unsqueeze(1), radius)[:, 0]
    p_sum, g_sum = pred_soft.sum(dim=(1, 2)), gt_hard.sum(dim=(1, 2))
    prec_num = (pred_soft * gt_band).sum(dim=(1, 2))
    rec_num = (gt_hard * dilated_pred).sum(dim=(1, 2))
    precision = (prec_num + eps) / (p_sum + eps)
    recall = (rec_num + eps) / (g_sum + eps)
    loss = precision_weight * (1.0 - precision) + (1.0 - precision_weight) * (1.0 - recall)
    return loss.mean()
\end{lstlisting}

\texttt{ToleranceBandLoss} applies this per class over a \texttt{class\_config} dict with the same
\texttt{\{class\_id: \{"name", "tolerance"\}\}} shape as \texttt{ROAD\_BUILDING\_CONFIG} in
\texttt{dtaf1.py}, and macro-averages across the configured linear and polygon classes.

\subsection{Soft Boundary Loss (Boundary F1 Analog)}
\label{subsec:boundary-loss}

The soft boundary map uses the same soft erosion and dilation operations that
Section~\ref{subsec:cldice-loss} introduces for soft-skeletonization:
$\mathrm{boundary}(x) = \mathrm{dilate}(x) - \mathrm{erode}(x)$, the morphological gradient, which
is $0$ in flat interior and exterior regions and saturates to exactly $1.0$ at a hard, confident
class edge. \texttt{SoftBoundaryLoss} then applies \texttt{soft\_tolerance\_pair\_loss} from
Section~\ref{subsec:tolerance-loss} to this soft boundary map on the predicted side, against a
thresholded boundary map of the one-hot ground truth computed under \texttt{no\_grad}, instead of
to the full class mask.

\subsection{Soft-clDice Loss (clDice Analog)}
\label{subsec:cldice-loss}

This term implements the soft-skeletonization of \citet{shit2021cldice} directly, by iterating
$\mathrm{soft\_erode}(x) = -\mathrm{maxpool}(-x)$, $\mathrm{soft\_dilate}(x) = \mathrm{maxpool}(x)$
and $\mathrm{soft\_open}(x) = \mathrm{soft\_dilate}(\mathrm{soft\_erode}(x))$ and accumulating the
skeleton response across scales as the original reference algorithm does. It is applied to the
model's continuous probability map instead of a binary mask passed through a discrete
\texttt{skeletonize()}:
\begin{align}
  \mathrm{tprec}_c &= \frac{\sum(\mathrm{skel}(p_c) \cdot g_c) + \epsilon}{\sum(\mathrm{skel}(p_c)) + \epsilon} \\
  \mathrm{tsens}_c &= \frac{\sum(\mathrm{skel}(g_c) \cdot p_c) + \epsilon}{\sum(\mathrm{skel}(g_c)) + \epsilon} \\
  \mathrm{soft\_clDice}_c &= \frac{2 \cdot \mathrm{tprec}_c \cdot \mathrm{tsens}_c}
                                  {\mathrm{tprec}_c + \mathrm{tsens}_c + \epsilon}, \quad
  \mathrm{loss}_c = 1 - \mathrm{soft\_clDice}_c
\end{align}

\textbf{Known limitation.} Unlike the evaluation metric, soft-skeletonization runs for a fixed
number of iterations ($\mathrm{iters}=10$ by default) instead of to convergence, so width
invariance only holds up to the width that this many iterations can fully erode. On a
$32\times32$ synthetic scene with a ground-truth road 3px thick, the
soft-clDice loss is $4.77\times10^{-7}$ for a matching 3px prediction and the same
$4.77\times10^{-7}$ for a prediction three times thicker (9px) on the same centerline, so there is
no measurable width sensitivity up to a $3\times$ ratio. Plain soft Dice on the same 9px input
scores only $0.500$, which confirms that soft-clDice behaves differently from plain Dice and is not
simply saturating numerically
(\texttt{tests/test\_losses\_sanity.py::\allowbreak{}TestSoftClDiceLoss::\allowbreak{}test\_width\_insensitivity}).

\subsection{Point-Heatmap Regression Loss (Point F1 Analog, Reformulated)}
\label{subsec:heatmap-loss}

Since the Hungarian matching of Section~\ref{subsec:pointf1} has no useful gradient, this term
recasts point supervision as dense Gaussian-heatmap regression in the style of CenterNet
\cite{zhou2019centernet}. We extract the centroid of each ground-truth
point instance with the same \texttt{scipy.ndimage.label} and \texttt{center\_of\_mass} pipeline
that \texttt{\_instance\_centroids} in \texttt{point\_f1.py} uses at evaluation time, here only for
target construction under \texttt{no\_grad}, and burn it into a Gaussian blob on a target heatmap,
combining overlapping Gaussians with an elementwise max. The nearest integer pixel of every
centroid is stamped to exactly $1.0$ so that the positive term below always fires; otherwise a
sub-pixel centroid peaks below $1.0$ and receives no positive supervision at all, which was the
failure of the first scaled run (Section~\ref{subsec:scaled-results}). The point probability $p$
is trained against this target with a penalty-reduced pixelwise focal loss (the CornerNet and
CenterNet formulation \cite{law2018cornernet,zhou2019centernet}):
\begin{align}
  H(x) &= \max_{c \in \mathrm{centroids}} \exp\left(-\frac{\|x-c\|^2}{2\sigma^2}\right) \\
  \ell^{+}(x) &= -(1-p(x))^\alpha \log p(x) \quad \text{if } H(x) = 1 \\
  \ell^{-}(x) &= -(1-H(x))^\beta\, p(x)^\alpha \log(1-p(x)) \quad \text{otherwise} \\
  \mathrm{loss} &= \frac{\sum_x \ell^{+}(x)}{N_{\mathrm{pos}}}
                 + \frac{\sum_x \ell^{-}(x)}{Z_{\mathrm{neg}}}
\end{align}
where $H$ is the target heatmap, set to exactly 1 at each $\mathrm{round}(c)$, and
$N_{\mathrm{pos}} = \max(1, \#\text{peak pixels in the batch})$, counted only over samples
whose source annotates points. The choice of the negative normalizer $Z_{\mathrm{neg}}$ has large
practical consequences (Section~\ref{subsec:scaled-results}). $Z_{\mathrm{neg}} = N_{\mathrm{pos}}$
is CenterNet's own normalizer and prices a false-positive pixel on the same scale as a missed
peak, while $Z_{\mathrm{neg}} = \#\text{negative pixels}$, a per-pixel mean, makes false positives
almost free. CenterNet applies its normalizer to a stride-4 output. At PLEM's full resolution
there are ${\sim}100{,}000$ background pixels per road intersection, roughly $40\times$ CenterNet's
design ratio, so neither choice is safe by default: in the real runs the per-pixel mean
over-detected $30\times$, and $N_{\mathrm{pos}}$ almost never fired at a fixed threshold. Either
way, the decoding threshold has to be calibrated on validation tiles.

\textbf{Independent point head.} The point probability is
$p = \mathrm{sigmoid}(\mathrm{logits}[:, \mathrm{point}])$, an output channel outside the
road/building/background softmax. The segmentation terms never see the point logits and the point
term never sees the segmentation logits, so point predictions cannot take pixels from roads or
buildings, as a point channel inside the softmax did when it flooded half of all SpaceNet test
pixels (Section~\ref{subsec:scaled-results}). A point may also coincide with a road pixel, as every
road intersection does. At inference, points are decoded as local maxima of $p$, by non-maximum
suppression over the whole stitched tile, above a threshold chosen by validation F1. Evaluation
still uses the Hungarian matching of \texttt{point\_f1.py}, so training and evaluation use
different formulations for points (Section~\ref{sec:discussion}).

\subsection{\texttt{PLEMMultiTaskLoss}: Combination and Multi-Source Class Masking}
\label{subsec:multitask-loss}

The combined loss adds a CE+soft-Dice base term, adapted from the existing
\texttt{combined\_loss} in \texttt{train\_unet.ipynb}, to the three geometry-aware terms above, each
with its own weight:
\begin{align}
  L = w_{\mathrm{ce\_dice}} L_{\mathrm{ce\_dice}} + w_{\mathrm{tol}} L_{\mathrm{tolerance}} +
      w_{\mathrm{cldice}} L_{\mathrm{cldice}} + w_{\mathrm{heatmap}} L_{\mathrm{heatmap}}
\end{align}

\textbf{Multi-source class masking.} In the final pipeline, SpaceNet tiles annotate roads,
buildings and road intersections, while Potsdam and SpaceNet6 tiles annotate buildings only (in
early development runs, Potsdam annotated buildings and points; Section~\ref{subsec:scaled-setup}).
Training one model on all sources jointly requires each sample to be supervised only on the classes
its source annotates. For the softmax classes, we add a large negative bias to a sample's
masked-out class channels before any softmax is taken:
\begin{align}
  \mathrm{logits}'[:,c] = \mathrm{logits}[:,c] + (1 - \mathrm{class\_mask}[:,c]) \cdot (-10^4)
\end{align}
Every term above is a function of softmax probabilities, so driving a masked channel's pre-softmax
logit to $-\infty$ makes its post-softmax probability vanish, and with it the channel's gradient
contribution to every term at once. One mechanism serves all four loss terms, so no term needs its
own masking code. It relies on target label maps never containing a class id that the sample's
source does not annotate, which holds by construction for the rasterizers in both
\texttt{datasets/spacenet.py} and \texttt{datasets/potsdam.py}
(Sections~\ref{subsec:realdata-setup},~\ref{subsec:scaled-setup}). The same mechanism handles
unlabelled areas within a source. A SpaceNet training patch that touches any area without public
building labels (Section~\ref{subsec:scaled-setup}) has building masked out for that patch, and any
building pixels in it are relabelled as background, so unlabelled buildings are never taught as
``not a building''. The independent point head (Section~\ref{subsec:heatmap-loss}) has no softmax
to mask, so it is excluded per sample instead: a sample whose source has no point labels
contributes nothing to the point term. \texttt{PLEMMultiTaskLoss.forward()} returns a dict holding
\texttt{"loss"} and each active sub-term as a detached float, so every sub-term can be logged per
epoch.
