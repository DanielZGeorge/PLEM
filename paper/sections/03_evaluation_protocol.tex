\section{Evaluation Protocol}
\label{sec:evalprotocol}

This section defines the six primitives PLEM uses to score a prediction against ground truth.
Three of them are also what the differentiable loss terms of Section~\ref{sec:method} approximate
during training.

\textbf{Shared notation.} Let $P$ and $G$ be $H\times W$ integer label maps (prediction and
ground truth) over the class set $C = \{0, 1, 2, [3]\}$. For class $c$, define binary masks
$P_c = (P = c)$ and $G_c = (G = c)$. Every primitive in this section is applied per class and then
reduced across the classes relevant to it, by a macro mean or a mean weighted by ground-truth
pixel count.

\textbf{Shared edge-case convention.} Every primitive below follows the same rule, which we
checked is identical across \texttt{dtaf1.py:43-51}, \texttt{cldice.py:51-56},
\texttt{boundary\_f1.py:68-72}, \texttt{point\_f1.py:109-120} and \texttt{apls.py:141-144}: if
both $P_c$ and $G_c$ are empty the score is $1.0$ (vacuously correct), and if exactly one of
$P_c, G_c$ is empty the score is $0.0$ (total failure).

\subsection{DTAF1 --- Distance-Tolerant, per-class F1}
\label{subsec:dtaf1}

DTAF1 matches pixels within a tolerance radius using the Euclidean distance transform (EDT,
\texttt{scipy.ndimage.distance\_transform\_edt}). $\mathrm{EDT}(1-M)(x)$ is the distance from pixel
$x$ to the nearest pixel of mask $M$:
\begin{align}
  \mathrm{TP}_{\mathrm{pred}} &= |\{x \in P_c : \mathrm{EDT}(1-G_c)(x) \le d_c\}| \\
  \mathrm{TP}_{\mathrm{gt}}   &= |\{x \in G_c : \mathrm{EDT}(1-P_c)(x) \le d_c\}| \\
  \mathrm{Precision}_c &= \mathrm{TP}_{\mathrm{pred}} / |P_c|, \quad
  \mathrm{Recall}_c = \mathrm{TP}_{\mathrm{gt}} / |G_c| \\
  F1_c &= \frac{2 \cdot \mathrm{Precision}_c \cdot \mathrm{Recall}_c}
               {\mathrm{Precision}_c + \mathrm{Recall}_c}
\end{align}
Both reductions across classes are always computed, and \texttt{reduction} selects which one is
reported as the top-level \texttt{dtaf1} key:
\begin{align}
  \mathrm{DTAF1}_{\mathrm{macro}} &= \tfrac{1}{|C|}\textstyle\sum_c F1_c \\
  \mathrm{DTAF1}_{\mathrm{weighted}} &= \left(\textstyle\sum_c n_c F1_c\right) \big/
    \left(\textstyle\sum_c n_c\right), \quad n_c = |G_c|
\end{align}

\begin{lstlisting}[language=Python, caption={Tolerance-matching core, \texttt{metrics/dtaf1.py:53-64}}]
dist_from_gt = distance_transform_edt(1 - g)
dist_from_pred = distance_transform_edt(1 - p)
tp_pred = int(((p == 1) & (dist_from_gt <= d)).sum())
tp_gt = int(((g == 1) & (dist_from_pred <= d)).sum())
precision = tp_pred / n_pred
recall = tp_gt / n_gt
f1 = (2 * precision * recall / (precision + recall)
      if (precision + recall) > 0 else 0.0)
\end{lstlisting}

The default tolerances (\texttt{DEFAULT\_TOLERANCES}) are 10\,px for roads and 2\,px for buildings
(Section~\ref{subsec:tolerance-radii} explains how they were chosen). The function signature is
\texttt{dtaf1(pred, gt, class\_config, reduction="macro") -> dict}, and it returns \texttt{dtaf1},
\texttt{dtaf1\_macro}, \texttt{dtaf1\_weighted} and \texttt{per\_class}. DTAF1 applies the
same formula to every class, so scoring a new class only needs a new \texttt{class\_config} entry,
and the
\texttt{ToleranceBandLoss} of Section~\ref{subsec:tolerance-loss} takes the same
\texttt{class\_config} shape.

\subsection{clDice --- Centerline Dice}
\label{subsec:cldice}

\begin{align}
  S_p &= \mathrm{skeletonize}(P_c), \quad S_g = \mathrm{skeletonize}(G_c) \\
  T_{\mathrm{prec}} &= |S_p \cap G_c| / |S_p|, \quad T_{\mathrm{sens}} = |S_g \cap P_c| / |S_g| \\
  \mathrm{clDice} &= \frac{2 \cdot T_{\mathrm{prec}} \cdot T_{\mathrm{sens}}}
                          {T_{\mathrm{prec}} + T_{\mathrm{sens}}}
\end{align}
clDice is insensitive to width, since a predicted road $3.3\times$ too thick still scores
$\mathrm{clDice}=1.000$ (Table~\ref{tab:failure-modes}, row 2), but it is brittle under offset: the
skeletons of the same road shifted by 5px share no pixels at all ($\mathrm{clDice}=0.000$, row 1).
This sensitivity to offset is what motivates DTAF1's distance-tolerant matching in place of a raw
skeleton intersection. The \texttt{SoftClDiceLoss} of Section~\ref{subsec:cldice-loss}
reimplements the width insensitivity differentiably, with a caveat discussed in
Sections~\ref{subsec:cldice-loss} and~\ref{sec:discussion}.

\subsection{Boundary F1 (BF) and the IoU Baseline}
\label{subsec:bf}

\begin{align}
  \mathrm{Precision} &= |\{x \in B_p : \mathrm{dist}(x, B_g) \le \tau\}| / |B_p| \\
  \mathrm{Recall} &= |\{x \in B_g : \mathrm{dist}(x, B_p) \le \tau\}| / |B_g| \\
  \mathrm{BF} &= \frac{2 \cdot \mathrm{Precision} \cdot \mathrm{Recall}}
                      {\mathrm{Precision} + \mathrm{Recall}}
\end{align}
where $B_p = \mathrm{boundary}(P_c)$ and $B_g = \mathrm{boundary}(G_c)$ are extracted
morphologically. The same module provides \texttt{iou()}, the pixel-overlap baseline we compare
against throughout Sections~\ref{sec:motivation} and~\ref{sec:expsetup}. The
\texttt{SoftBoundaryLoss} of Section~\ref{subsec:boundary-loss} computes the same soft
tolerance-band precision and recall as \texttt{ToleranceBandLoss}
(Section~\ref{subsec:tolerance-loss}), but on a soft boundary map instead of the full class mask.

\subsection{Point F1 --- Hungarian Instance Matching}
\label{subsec:pointf1}

The optional point class is road intersections in the trained-model pipeline
(Section~\ref{subsec:scaled-setup}) and was Potsdam trees in earlier work
(Section~\ref{subsec:realdata-setup}). Point F1 reduces connected-component blobs to centroids
(\texttt{scipy.ndimage.label} and \texttt{center\_of\_mass}) and then matches them by
tolerance-restricted Hungarian assignment (\texttt{scipy.optimize.linear\_sum\_assignment})
instead of greedy nearest-neighbor matching.

\begin{lstlisting}[language=Python, caption={Hungarian assignment core, \texttt{metrics/point\_f1.py:58-65}}]
dist = cdist(gt_c, pred_c)
big = tolerance * 1e6 + 1.0
cost = np.where(dist <= tolerance, dist, big)
row_ind, col_ind = linear_sum_assignment(cost)
valid = dist[row_ind, col_ind] <= tolerance
return int(valid.sum())
\end{lstlisting}

The clustered-points adversarial case in \texttt{TestPointInstanceMatching} justifies this choice:
greedy nearest-neighbor matching gets $\mathrm{TP}=1$ where Hungarian assignment finds the
globally optimal $\mathrm{TP}=2$ (formalized in Appendix~\ref{app:proofs},
Section~\ref{app:a6}). Point F1 has no differentiable analog in Section~\ref{sec:method}, because
Hungarian assignment and connected-component labeling give no useful gradient path back to
per-pixel logits. Section~\ref{subsec:heatmap-loss} instead recasts point supervision as heatmap
regression, a real mismatch between the training and evaluation formulations that
Section~\ref{sec:discussion} discusses.

\subsection{APLS --- Raster-Skeleton Average Path Length Similarity}
\label{subsec:apls}

No vector road graph survives into evaluation.
\texttt{datasets/common.py::\allowbreak{}rasterize\_lines} turns roads directly into a flat pixel
mask and discards the segment and graph structure; the vector labels are read only once, at
dataset-build time, to derive intersection points (Section~\ref{subsec:scaled-setup}). As such, we
approximate APLS entirely from raster skeletons (\texttt{metrics/apls.py}). We skeletonize the
predicted and ground-truth masks and build an 8-connected pixel-adjacency graph (\texttt{networkx},
with edge weight equal to Euclidean pixel distance). For sampled ground-truth control-point pairs
$(u,v)$ within one ground-truth connected component, we compare the ground-truth shortest-path
length $L_{\mathrm{gt}}(u,v)$ with the predicted shortest-path length between the nearest
snap-matched nodes of the predicted graph (\texttt{scipy.spatial.cKDTree}), scoring
$\max(0, 1 - |L_{\mathrm{pred}} - L_{\mathrm{gt}}| / L_{\mathrm{gt}})$ if both are matched and 0
otherwise. Control-point pairs are sampled grouped by source node, so one
\texttt{nx.single\_source\_dijkstra\_path\_length} call is shared across many targets instead of
running Dijkstra once per pair (complexity analysis in Appendix~\ref{app:complexity},
Section~\ref{app:b6}). APLS is deliberately sensitive to a failure that DTAF1's per-pixel tolerance
matching misses: once the skeleton fragments, shortest paths between control points either
lengthen sharply or disappear, so APLS collapses where DTAF1 does not. Graph shortest-path
recomputation has no tractable differentiable relaxation, so APLS and DTAF1-Topo
(Section~\ref{sec:topological}) stay evaluation-only (Section~\ref{sec:method}).

\subsection{CBHM --- Composite clDice/Boundary-F1 Harmonic Mean}
\label{subsec:cbhm}

\begin{align}
  \mathrm{clDice}_{\mathrm{mean}} &= \mathrm{mean}(\mathrm{clDice}_c : c \in \mathrm{linear\_classes}) \\
  \mathrm{BF}_{\mathrm{mean}} &= \mathrm{mean}(\mathrm{BF}_c : c \in \mathrm{polygon\_classes}) \\
  \mathrm{CBHM} &= \frac{2 \cdot \mathrm{clDice}_{\mathrm{mean}} \cdot \mathrm{BF}_{\mathrm{mean}}}
                        {\mathrm{clDice}_{\mathrm{mean}} + \mathrm{BF}_{\mathrm{mean}}}
\end{align}
We chose the harmonic mean deliberately, so that a single class scoring 0 collapses the whole
composite to 0. This makes CBHM the harsh foil of DTAF1's more lenient macro average: in the ``Road
shifted 5px'' row of Table~\ref{tab:failure-modes}, the same input gives $\mathrm{DTAF1}=1.000$ and
$\mathrm{CBHM}=0.000$.

These six primitives compose into the two final composites, \texttt{cbhm\_soft}
(Section~\ref{sec:composite}) and DTAF1-Topo (Section~\ref{sec:topological}), and into the three
geometry-aware \texttt{losses/} terms of Section~\ref{sec:method}.
